# WigglePlay for Android and iOS

An Expo shell around the WigglePlay web app. The whole web build (games, art, MediaPipe runtime
and models) ships inside the binary as `assets/web.zip`, is unpacked once on first launch and is
served to a WebView from a localhost server, so the app works fully offline.

```bash
npm install
npm run ios        # packs the web app, generates ios/, builds and runs on a simulator
npm run android    # same for Android (needs the Android SDK and a JDK 17+)
npm run typecheck
npm test
```

- `scripts/sync-web.mjs` builds `../` with a root base path and packs it (stored zip).
- `src/bundle.ts` unpacks the zip into the documents folder and stamps it with the bundle version
  so an app update re-extracts it.
- `src/server.ts` serves that folder on `http://127.0.0.1:<port>` (a secure context, which the
  camera needs).
- `App.tsx` asks for camera and microphone permission, shows the unpacking progress and then
  loads the WebView locked to the local origin.
- CocoaPods needs a UTF-8 locale on macOS with Ruby 3.4 (`LANG=en_US.UTF-8`); the npm scripts set it.
- Native projects (`ios/`, `android/`) are generated by `expo prebuild` and are not committed.
